# SBOMScan 授權功能檢查報告

檢查日期：2026 年 10 月 18 日。

已修正本次發現的授權檢查缺口。以正式 Docker 映像重跑後，32 個實際 API 情境、239 項斷言、6 個瀏覽器情境，以及 62 條已註冊且需登入的寫入路由之唯讀檢查均通過。Go 全套測試、66 個前端測試與前端正式建置通過。開發測試建置亦另完成 240 項 API 斷言。

**Basic、Professional、Enterprise 目前仍是相同內容的評估範本。** 三個名稱的啟用都可運作，但正式方案的差異尚未設定。系統依授權檔內簽署的期限、額度與功能清單判斷權限，不會因為名稱是 Enterprise 就自動放行全部功能。

## 實測方式

API 測試使用真實 Keygen CE、新建的暫時 Product／Policies／Licenses／Machines，以及獨立 PostgreSQL 測試容器中的兩個資料庫。測試結束已刪除暫時 Product 與測試容器；現有供應商 Product 保留。沒有將測試授權匯入目前的客戶產品，也沒有修改其業務資料或授權方案。

瀏覽器測試使用正式建置的前端搭配模擬 API，檢查按鈕、模組切換、唯讀與前端例外；不呼叫真實產品的變更 API。真實的授權簽章、期限、部署數量、Session 與後端權限由 API 測試驗證。

到期測試使用實際核發、約十秒後到期的 License。寬限期、活動逾時與時間回撥測試則調整隔離測試狀態／資料庫的時間欄位，沒有修改主機時間或等待十五分鐘。

## 功能模組結果

已測試無付費模組、單獨授予四種模組，以及全部模組開啟；另以 Go 測試交叉覆蓋三種模式的路由權限。

| 功能 | 沒有對應模組 | 有模組且授權有效 | 唯讀時 |
|---|---|---|---|
| 一般專案新增／修改／刪除 | 有效 License 可使用基礎 CRUD | 可使用 | 禁止 |
| 上傳與掃描、重新掃描、掃描排程 | 禁止 | 通過授權門檻 | 禁止 |
| Collector 建置、工具下載、驗證與匯入 | 禁止 | 通過授權門檻 | 禁止 |
| Collector ZIP 經一般上傳入口 | 缺 Collector 時禁止，即使有 Scan 也一樣 | 需 Scan 與 Collector | 禁止 |
| 修補狀態、摘要與附件寫入 | 禁止 | 通過授權門檻 | 禁止 |
| 漏洞資料庫更新、匯入、排程 | 禁止 | 通過授權門檻 | 禁止 |
| 漏洞資料庫離線打包腳本下載 | 禁止，含 HEAD | 可下載 | 禁止 |
| 查看既有專案、漏洞、Collector 紀錄 | 可以 | 可以 | 可以 |
| 匯出既有報告 JSON、SBOM、PDF | 可以 | 可以 | 可以 |

「通過授權門檻」的 API 測試會確認有授權時能進入業務處理器，沒有授權時回覆 403。部分正向請求刻意使用不存在的工作或無效資料，因此業務處理器會回覆 400／404／422；這些情境不是一次完整的掃描或編譯測試。JSON、SBOM 與 PDF 匯出則確實產生並檢查了內容，不只是觀察到非 403。

## 部署與在線人數結果

| 情境 | 結果 |
|---|---|
| 同一 License 允許兩套獨立部署 | 兩套成功啟用 |
| 第三個設備識別碼啟用 | 拒絕，沒有多占用第三個名額 |
| 每套限制兩人，使用兩個獨立產品資料庫 | 各自可使用兩人，互不借用額度 |
| 第三位有效使用者請求 | 429 |
| 八位使用者同時競爭兩個名額 | 恰好兩位成功、六位遭拒，沒有超額 |
| 同一使用者持有兩個 Session | 共用一個人數名額 |
| 登出、強制登出 | 有效名額可被下一位使用者取得 |
| 超過九十秒沒有活動 | 釋放名額 |
| Session 到期 | 釋放名額 |
| 帳號停用 | 不再占用有效名額 |

名額在實際請求／Heartbeat 時取得，不是只要拿到登入 Token 就永久占用。授權恢復、登入資訊與登出等回復入口不會因唯讀而失效。管理員的一般產品操作仍依在線人數上限計算。

## 簽章與背景作業結果

修改簽章內容、錯誤簽章公鑰、錯誤 Account／Product、錯誤設備、錯誤檔案種類、無期限資料、尚未開始、已過期與非正整數人數等情境均被拒絕。無效的新檔案不會覆蓋原本有效的授權。

產品重啟會保留設備識別與有效檔案；複製檔案到另一個安裝識別碼會遭拒。已見時間回撥超過五分鐘時會進入 clock_error。

排程掃描、自動掃描及來源碼／容器分析的授權檢查有回歸測試，確認失效時先停止，再進入儲存與分析程序。Collector ZIP 的一般上傳、手動掃描、重新掃描、排程與結果關聯入口也補上 Collector 檢查。漏洞資料庫更新與 Collector 建置原有的背景啟動／階段檢查已核對接線。

## 本次修正

1. 未設定模式時，Go 原本預設 disabled；改為 offline，避免漏填設定就放行。
2. Collector ZIP 可從一般上傳入口進入，但原本只檢查 Scan；補齊上傳、掃描、重掃、排程與內部結果關聯的 Collector 檢查。
3. 原本整個 analyzer 路徑都需要模組，造成唯讀無法查看既有紀錄；改為允許紀錄列表，建置、下載與匯入仍受限制。
4. 漏洞資料庫打包腳本是 GET，原本未要求更新模組；補齊 GET／HEAD 權限。
5. 無付費模組的有效授權原本可能回傳 features 為 null；API 改回傳空陣列，前端亦保留相容處理。
6. 來源碼、SAST 與容器分析補上新階段開始前的授權檢查；Collector 工作在分析階段與報告發布前也重新確認模組。
7. 前端共用授權狀態，讓掃描、重掃、排程、Collector、修補寫入與漏洞資料庫的主要入口跟隨模組及唯讀狀態；查看與報告入口保留。建立專案附帶檔案時，也避免先建立專案才發現缺少 Scan。
8. 正式 Docker 建置以連結時設定關閉 disabled 模式，避免客戶單靠環境變數停用授權；直接從 Go 原始碼建立的開發版本仍可使用此模式。正式映像的拒絕行為已直接實測。

## 使用上的邊界

- 正式方案的實際功能與額度仍需在 Portal 定義。測試中的臨時方案組合不會寫回既有商業方案。
- 前端每三十秒更新授權狀態。到期或中央變更與畫面更新之間可能有短暫落差；後端仍在每次受保護請求重新檢查並拒絕不允許的操作。所有 62 條已註冊且需登入的寫入路由均納入唯讀檢查，前端不是權限邊界。
- online 中央變更在下一次成功驗證／手動更新時生效。activation 與 offline 的舊檔案無法即時接收撤銷。
- 已經啟動的外部工具不保證在到期瞬間被強制終止；工作會在後續授權檢查階段停止，不會繼續開啟受禁止的新階段或發布被檢查擋下的結果。
- 客戶控制 Docker Host 時仍可能偽造識別碼、修改程式／設定或回復狀態快照，不能保證離線授權絕對無法繞過。
- 本次驗證授權限制，不涵蓋掃描器偵測準確率、所有 OS 的 Collector 交叉編譯，或一次完整的外部漏洞資料庫下載。
